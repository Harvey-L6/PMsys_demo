# PMsys_demo｜專案管理與半自動通知系統

以 **Google Sheets、Google Apps Script 與 Bootstrap** 建立的專案追蹤系統。管理者透過試算表維護專案與人員資料，專案成員則透過專屬網頁回報進度、管理任務及維護組員清冊。

本 repo 為作品原始碼展示版，展示試算表資料結構、Web App 介面、專案連結與通知流程的整合方式。線上互動示範另行部署；repo 不包含實際試算表、Script Properties 設定值或業務資料。

## 專案目的

將分散於試算表、信件與附件中的專案資訊，整理為可持續更新的工作流程：

- 以試算表作為管理者的資料維護入口。
- 提供各專案專屬的進度回報與任務管理網頁。
- 將專案更新、任務異動與寄件結果寫入紀錄分頁。
- 由管理者觸發通知作業，減少逐封整理信件與複製專案連結的工作。

## 主要功能

| 模組 | 功能 |
| --- | --- |
| 專案總覽 | 顯示專案資訊、Owner、時程、預期效益、驗收標準、ROI 與里程碑；提供部分欄位編輯 |
| 進度回報 | 更新最新進度與下一步 Action，並將本次更新寫入歷史紀錄 |
| 任務牆 | 新增與編輯任務，維護負責人、狀態、進度、預期完成日期與實際完成日期；區分進行中與已完成任務 |
| 組員清冊 | 顯示 Owner 與組員資訊，支援新增／移除組員及新增員工主檔資料 |
| 附件上傳 | 將回報附件存入專案 Google Drive 資料夾，並記錄檔案連結 |
| 專案初始化 | 為新專案產生 Token、建立 Drive 資料夾與專屬網站連結 |
| 半自動通知 | 發送立案通知、回報提醒及報告通知；收件者為 Owner，有信箱的組員列入副本 |
| 操作紀錄 | 保存總表異動、任務異動與寄件結果 |

通知由管理者從試算表自訂選單觸發。此版本沒有內建依日期自動排程的通知功能。

## 技術與架構

| 技術 | 用途 |
| --- | --- |
| Google Sheets | 儲存專案、任務、人員、組員與異動紀錄 |
| Google Apps Script（V8） | 讀寫試算表、建立專案資料夾、處理網頁請求及寄送通知 |
| HTML Service | 依專案資料產生 Web App 頁面 |
| `google.script.run` | 前端非同步呼叫 Apps Script 後端函式 |
| Bootstrap 5.3.0 | 頁籤、表單、卡片、狀態標籤與 Modal 介面 |
| Google Drive／Gmail | 儲存附件與發送 HTML 通知信 |

系統採用**綁定 Google Sheets 的 Apps Script 專案**，以 `SpreadsheetApp.getActiveSpreadsheet()` 存取資料。前端畫面由 Apps Script 模板產生，無須另外建立 Node.js 伺服器或安裝 npm 套件。

## 原始碼結構

| 檔案 | 職責 |
| --- | --- |
| [SheetAdmin.gs](SheetAdmin.gs) | 試算表自訂選單、專案初始化、通知信與寄件紀錄 |
| [WebApp.gs](WebApp.gs) | 網頁入口、資料查詢、進度／任務／人員更新、附件儲存與異動紀錄 |
| [Index.html](Index.html) | 專案總覽、任務牆、組員清冊與各項編輯視窗 |
| [appsscript.json](appsscript.json) | 時區、V8 執行環境與 Web App 設定 |

主要入口：

- `onOpen()`：在試算表建立「⚙️ 專案管理工具」選單。
- `initNewProjects()`：補齊專案 Token、資料夾與專屬連結。
- `doGet(e)`：依網址中的專案 Token 載入對應頁面。
- `submitProjectUpdate(formData)`：處理進度回報、附件與歷史紀錄。
- `saveTask(token, taskData)`：新增或更新專案任務。
- `sendInitiationEmails()`、`sendReminderEmails()`、`sendReportEmails()`：三種通知入口。

## 操作流程

1. 管理者於「專案追蹤總表」建立專案，並維護「員工主檔」與「組員清冊」。
2. 從自訂選單執行專案初始化，產生 Token、Drive 資料夾與專屬連結。
3. 管理者選擇通知種類，系統從總表及人員資料組合信件內容並寄送。
4. 專案成員由專屬連結進入網頁，回報進度、更新任務或上傳附件。
5. 系統將更新內容與寄件結果寫入對應紀錄分頁。

## 重現環境與設定

以下提供自行重現此版本的設定方式。請建立自己的測試試算表與資料夾，並使用虛構資料。

### 1. 建立資料分頁

建立 Google Sheets，新增下列 **7 個分頁**。第一列為欄位名稱；名稱請與程式一致。

| 分頁名稱 | 用途 |
| --- | --- |
| 專案追蹤總表 | 專案基本資料、目前進度、連結與通知狀態 |
| 總表異動紀錄 | 專案資訊與進度的異動紀錄 |
| 任務牆 | 各專案目前任務 |
| 任務牆異動紀錄 | 任務新增／更新的紀錄 |
| 組員清冊 | 專案編號與成員的對應 |
| 員工主檔 | 人員姓名、職稱、單位與信箱 |
| 寄件紀錄 | 通知種類、收件者與寄件結果 |

### 2. 設定欄位

下列欄位依目前原始碼整理。可加入其他管理欄位，但不要更動程式使用的名稱。

**專案追蹤總表**

- 識別與人員：`專案編號`、`專案名稱`、`需求提出者`、`Owner (一級主管指派)`、`專案Token`
- 專案資訊：`進度狀態`、`專案續行評估`、`預期效益(目的)`、`驗收標準`、`ROI`、`Milestone(里程碑)`
- 時程：`專案開始日期`、`預期Deadline`、`實際完成時間`、`回報Deadline`、`下次進度報告日期`
- 回報與連結：`最新進度回報`、`下一步Action`、`檔案連結(選填)`、`最新更新日期`、`雲端資料夾連結`、`專屬網站連結`
- 通知狀態：`立案通知`、`回報提醒`、`報告通知`

**總表異動紀錄**

`專案編號`、`專案名稱`、`異動編號`、`預期效益(目的)`、`ROI`、`驗收標準`、`Milestone(里程碑)`、`預期Deadline`、`進度彙報內容`、`下一步Action`、`檔案連結`、`更新日期`

**任務牆與任務牆異動紀錄**

兩個分頁可使用相同欄位：

`專案編號`、`專案名稱`、`任務編號`、`Owner`、`任務內容`、`狀態`、`任務進度回報`、`建立日期`、`預期Deadline`、`完成日期`、`最後編輯日期`、`異動日期`

**員工主檔**

`人員姓名`、`職稱`、`mail`、`單位`

**組員清冊**

前兩欄依序為 `專案編號`、`成員姓名`；第三欄可設為 `備註`。新增組員功能依這個順序寫入資料。

**寄件紀錄**

`專案編號`、`專案名稱`、`信件種類`、`收件者`、`寄件結果`、`寄件時間`

### 3. 匯入 Apps Script

1. 從試算表開啟「擴充功能 → Apps Script」，建立綁定專案。
2. 將 `SheetAdmin.gs` 與 `WebApp.gs` 加入腳本專案。
3. 新增名為 `Index` 的 HTML 檔案，貼入 `Index.html` 的內容。
4. 在專案設定中顯示 `appsscript.json`，依 repo 的 manifest 設定執行環境；Web App 存取方式依自己的示範需求設定。
5. 儲存後重新開啟試算表，確認出現「⚙️ 專案管理工具」選單。

### 4. 設定 Script Properties 與部署

在 Apps Script「專案設定 → 指令碼屬性」設定：

| 屬性名稱 | 內容 |
| --- | --- |
| `FolderID` | 自己建立的 Google Drive 專案根資料夾 ID |
| `WebURL` | 自己部署的 Web App 正式網址，通常以 `/exec` 結尾 |

先建立自己的 Drive 根資料夾並設定 `FolderID`，再將 Apps Script 部署為 Web App，將部署網址填入 `WebURL`。首次執行需要完成 Google 授權。

Repo manifest 目前為 `USER_DEPLOYING` 與 `ANYONE_ANONYMOUS`，表示以部署者身分執行、允許匿名存取。自行重現時應確認實際部署設定符合使用對象；專案 Token 連結不是完整的帳號與角色權限系統。

### 5. 建立示範專案

1. 在「員工主檔」填入虛構姓名、職稱與單位；需要測試通知時，信箱填入自己可接收的測試信箱。
2. 在「專案追蹤總表」填入唯一專案編號、專案名稱與 Owner。Owner 姓名需與員工主檔一致。
3. 初次建立時，`專案Token`、`雲端資料夾連結` 與 `專屬網站連結` 可留空。
4. 從試算表選單執行「一鍵初始化新專案」，再開啟產生的專屬連結。
5. 依需求測試進度回報、任務新增／編輯與附件上傳。

專案編號、Token 及員工姓名應保持唯一。此版本以姓名對應員工資料，不另外使用員工 ID。

### 6. 測試通知

從試算表選單選擇「立案通知」、「回報提醒」或「報告通知」。

系統會處理總表中**該通知狀態欄位為空白**的專案，將通知寄給 Owner 並副本給有信箱的組員；成功後回填發送時間，失敗時記錄原因。

若要再次發送某種通知，需先清空該專案對應的通知狀態欄位。寄件作業會實際發信，測試時請使用自己的收件信箱。

## 展示範圍

此版本用於展示專案管理流程與 Google Workspace 整合實作，保留原有功能設計：

- 輸入資料與通知狀態由管理者透過試算表維護。
- Web App 以專案 Token 對應資料，未提供完整帳號、角色權限及多使用者並行控制。
- 上傳介面目前限制每次最多 5 個檔案、總容量 20 MB；這是前端檢查，後端未提供同等限制。
- 適合以獨立測試資料重現概念流程；正式業務環境需另外完善授權、資料驗證與操作管理。

## 設定與資料分離

部署網址與 Drive 根資料夾 ID 透過 Script Properties 設定，實際專案、人員與寄件資料保存在各自的 Google Sheets 中，未納入此 repo。

公開展示時，請只放示範用原始碼與虛構資料，避免將實際試算表匯出檔、專案 Token 連結或個人 Google 設定提交到 repo。
